# Agent Note: DML 内部文件路径检测与受限修复

Status: implemented

## Problem

同一 infohash 的原始种子路径不一定等于源下载器现用路径。客户端清洗 U+200E 或用户改名后，仅导出 .torrent 会让目标在错误的内部路径查找数据。文件大小或做种状态不能证明路径和内容正确；Transmission rename-path 又可能真的改动共享磁盘文件，不能把它当成无副作用的元数据接口。

## Decision

`transfer_path_detect_enabled` 默认开启，`transfer_path_auto_repair` 默认关闭。自动检测只读；发现差异保留源与目标，转移记录提供“检测/修复路径”入口，先展示差异，再用预览指纹确认执行。不可见字符在展示层显式标为 U+ 编号，不据此清洗或猜测文件名。

检测以同 hash、客户端文件索引和大小建立映射。修复仅接受唯一根名称替换，源任务完整、目标已暂停且无错误；执行时重读现场和指纹。浏览器不能提供磁盘路径，API 只定位既有转移记录，并与校验队列共用锁。

磁盘安全门仅接受可证明 RPC socket 由本机唯一 Transmission 进程持有的现场，通过 `/proc/<pid>/root` 核验目标命名空间。旧根与旧根 `.part` 必须均不存在，新路径文件类型/大小匹配、无符号链接、独立未完成目录关闭。远端、容器隔离或权限不足导致无法证明时明确拒绝；不新增 SSH 配置或凭据。这意味着 QNAP 容器中的检测可用，但手动修复可能被安全门阻止。

执行前持久化 `path_repair_verifying` 隔离阶段，再单次对齐根名称、提交真实校验。阶段内不回滚删目标、不删源、不启动未完成任务、不自动重试失败的改名。不借用旧校验或 H&R 许可；完成仅表示本次校验确认完整并保留源，后续行为仍走原有转移判断。此人工入口不改变[既有目标现场协调](../bug-fix/2026-11-02-dml-transfer-reconciliation.md)的普通只读协调边界。

## Alternatives considered

- 统一移除不可见字符：实现简单，但合法文件名可因清洗碰撞，也无法覆盖主动改名，故不采用。
- 通过 SSH 核验并修复远端：能覆盖 QNAP 容器外下载器，但增加凭据、权限与跨进程生命周期管理；本轮选择受限模式，不引入该通道。
- 直接调用 rename-path：减少环境约束，但旧文件存在时会真实改磁盘，可能影响其他辅种任务，故必须先核验现场。

## Consequences

不再把路径差异一直当作普通校验等待；代价是额外 RPC 查询（同记录检测限频 60 秒），且受限安全门会拒绝不少远端或目录内改名场景。Linux 进程/文件核验不是跨进程文件系统锁，外部客户端在核验与 RPC 之间改现场仍存在竞态；不宣称对不受控并发绝对安全。若要扩大支持范围，必须先解决远端可信现场和排他操作契约，而非放松检测。
