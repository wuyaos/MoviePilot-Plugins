# Agent Note: 转移历史清理与业务恢复状态分离

Status: implemented

## Problem

转移“最近记录”直接投影来源索引。这个索引也是重试、校验与删源的业务依据，不能因为用户清理面板就删除或覆盖；已有模块数据清理还会清统计，不符合只清展示的意图。

## Decision

`POST /transfer_history_clear` 只维护独立的 `transfer_history_snapshots`，值为来源记录键到整条记录规范 JSON 的 SHA-256 映射。清理覆盖全部页，而非当前筛选／当前页；前端二次确认后调用。接口沿用宿主 bearer 鉴权，不要求启动转移模块。

只对 `completed`、`failed`、`rolled_back` 做快照，排除 H&R 保护、请求删源但尚未完成及目标仍在校验队列的记录。队列身份采用目标下载器与目标 hash（`downloader::hash`），不使用来源记录键。规范序列化失败则保留可见。

查询先按当前队列和安全条件重新判断，再比较整条记录指纹，只隐藏完全未变的结束记录，随后筛选和分页。任意业务字段变化、重入队列、新事务替换都会重新显示。清理不会写事务、来源索引、校验队列或累计统计，也不调用下载器；并发时最多多显示记录，不覆盖 worker 的写入。

## Alternatives considered

- 直接删除结束记录：能回收空间，但会丢失恢复／归属依据，不符合避免误伤要求。
- 写入每条记录的 `history_hidden`：可复用旧展示机制，但读改写会与 worker 竞争，可能覆盖新保护状态，故不作为新入口实现。
- 只记时间戳或展示字段哈希：空间更小，但不能发现未投影的安全字段变化；采用整条记录指纹。
- 复用模块数据清理：已有接口，但它会清转移统计，范围不符。

## Consequences

“清理”是展示隐藏，不是磁盘回收，业务记录和累计统计保留。快照仅保留本次仍符合条件的记录，状态变化后的记录可再次清理。接口不返回或保存完整 tracker URL 等额外敏感信息。

离线路由测试覆盖跨页、重复清理、统计／物理索引不变、在途／待删源／H&R 保留、目标队列身份、隐藏后重新入队、非展示字段变化、记录替换及写入竞态。真实 QNAP 操作未作为本地验证的一部分。
