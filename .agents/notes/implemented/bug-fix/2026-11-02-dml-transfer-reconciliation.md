# Agent Note: DML 共存现场协调与当前删源意图

Status: implemented

## Problem

已完成历史只能证明曾经执行过转移，不能证明目的端现在仍完整、仍在正确路径或已带齐业务标签。首次转移关闭删源后再开启，整条跳过历史会永久留下源任务。Transmission 的标签接口为整组替换，转移标签与站点标签分步写入又会相互覆盖。

## Decision

源/目的共存时重读现场，验证 hash、路径、完整性及错误态；不删除、重加或重新校验既有目的任务。属于本插件的历史目标使用当前任务删源设置，外部已有目标使用当前删重复设置；标签补齐是独立结果，不是删源许可。TR 写入合并已有标签，False 是失败；后处理重新读取业务标签，防止站点标签覆盖它。

既有目的任务未经历本次真实校验，不能借历史 target_verification_started 或 completed 解除 H&R。正常新转移仍保留真实校验后的 H&R 授权链。自动开始仅表示发出请求，下一轮现场确认做种才允许继续。观察模式不得更新协调事务或写下载器。

在途事务在删除前重新匹配当前启用任务的源/目的下载器与任务名，唯一匹配才解析当前 delete_source。inherit 使用 `_transfer_delete_source_default`，不能退回可能已失同步的 `_deletesource`；移除、禁用或匹配不唯一则保留源任务。旧任务缺字段继续使用旧默认，前端保存时显式保留原生效值，不自动改成继承。

全局删除开关恢复可编辑，任务新建/编辑显示“继承全局（当前：开启/关闭）”，任务列表实际生效值只消费后端投影，不以尚未保存的草稿冒充运行设置。沿用既有样式。这一项替代[统一布局笔记](../architecture/2026-10-30-dml-unified-data-layout.md)中隐藏默认设置的决定，其余布局决定不变。

## Alternatives considered

- 继续跳过 completed 历史：查询少且简单，但无法补标签或处理用户后开删源的意图，故不采用。
- 对已有目的种子重新校验以恢复 H&R 授权：可获得新证据，但会打断已在做种的任务；本轮要求不改变目的端现有任务，故保留普通 H&R 闸门，不借历史许可。
- 用转移开始时的 delete_source_requested 快照：事务自包含，但用户关闭当前设置后仍可能不可逆删源，故删除边界重新读取当前配置。

## Consequences

共存场景增加查询次数；查询失败、身份/路径不符、目标未完整及 H&R 保护会保留源任务并展示细分结果。TR 合并基于读取快照，读取与写入之间外部并发改标签仍存在窗口，本轮不引入跨进程锁或泛化重试。

离线回归覆盖观察边界、标签共存和 False 回执、旧三补标签不重加、当前设置相反于旧键、任务移除/禁用/歧义、校验中/错误/路径异常、H&R 不借历史许可及自动开始。真实 Vue/Vuetify 组件浏览器检查全局开关保存、下载器路线、新任务继承文案与 H&R 配置保留。该检查使用内存 API，不代表真实 MoviePilot 宿主或 QNAP 下载器验收；本轮不部署、不提交、不推送。

历史笔记检索：统一布局笔记的隐藏默认值决定被部分替代并互链；其余命中为无关签到契约，未修改。没有重写或归档仍有效的布局决定。
