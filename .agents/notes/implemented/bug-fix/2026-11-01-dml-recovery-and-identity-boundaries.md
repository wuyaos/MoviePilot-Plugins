# Agent Note: DML 恢复账本与多下载器身份边界

Status: implemented

## Problem

下载器写入和插件状态保存不处于同一事务。RPC 成功后遇到 stop，或 qB 普通/备用限速的第二个 RPC 失败，可能留下实际限速却没有恢复凭据。多下载器可包含同一 hash，升级遗留的单来源配置也不能证明删除事件来自哪个下载器。仅覆盖单下载器、全部 RPC 成功的测试不能约束这些路径。

## Decision

- 限速接管按每个已成功 RPC 提交进度。`adapter/upload_limit.py` 的可选 `on_written` 回调在成功调用后立即提交对应字段；`modules/uploadlimit/service.py` 合并完整快照并以 `committed_write=True` 持久化。停止检查不能取消已经发生的外部写入记录。恢复保留 compare-and-set，部分恢复失败仍保留可重试账本。
- 同步删除只把事件明确携带的 downloader 当作身份。旧 `_fromdownloader` 可以提供检索候选，不能替事件选择来源；无身份且同 hash 匹配多条来源时拒绝删除，不扩为全部删除。失败不写成功去重缓存，因此后续可重试。
- 重命名的普通重试和转移后处理/补刀均贯穿实际 downloader，成功与失败记录都按同一身份隔离；未知来源不通过裸 hash 覆盖其他下载器记录。
- H&R 站点模板 ID 支持字符串（如 `dmhy`），历史数字 ID 保持兼容。模板标识不等于数据库整数主键；持久化再加载也必须保持有效身份。
- 整理失败只在已核实的本地下载根范围内处理本地文件。源存储及保护身份不明时不把事件路径当作已获授权的本地删除目标。已有 rt 观察边界不因转移/标签修补而放开。

## Alternatives considered

1. 只在每轮结束保存限速状态：写盘更少，但无法覆盖写后 stop 和第二 RPC 失败，故不保留该方案。没有真实写入的轮次仍沿用轮末保存。
2. 用旧单来源配置补齐缺失身份：更兼容老事件，但升级后的多来源同 hash 会选错破坏性目标，故只用于候选检索，不用于裁决。
3. 缺身份时对所有同 hash 来源操作：可以省去人工定位，但扩大了事件的删除权限，故采用歧义拒绝。

## Consequences

每个成功全局限速 RPC 增加一次状态保存；宿主状态存储失败与外部写入仍不具备原子性，本补丁不宣称实现跨系统事务。歧义事件和未知存储事件可能需要补齐身份后重试，这是避免误删的取舍。前端仅修正清理预览、兼容字段和选择项语义，保留既有样式。

## Testing

后端全量 956 passed；前端 158 passed，Vite 构建通过。反例使用离线下载器替身，不向真实任务执行删除、转移或限速。`test_review_recovery_regressions.py` 在第二 RPC 内检查第一步落盘，并模拟重启恢复；`test_sync_delete_retry_identity.py` 覆盖保留旧来源字段的歧义拒绝；`test_transfer_observe.py` 通过真实记录保存链验证两个转移命名入口的隔离。独立补审三项遗漏均关闭。真实宿主部署验收另行记录，不以这些离线结果代替真实业务验收。
