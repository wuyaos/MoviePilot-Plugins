# Agent Note: 自动删种累计做种计时与执行复查

Status: implemented

## Problem

自动删种将完成后经过时间当作做种时间，缺失完成时间时还从添加时间计时，暂停及下载中的任务可能被过早选中。执行阶段虽重读下载器，却仅确认hash存在，扫描后标签等条件变化仍可能执行旧候选。配置页体积帮助提示逗号分隔，而后端只支持连字符。

## Decision

做种时长只使用qB seeding_time、Transmission seconds_seeding/secondsSeeding累计秒数，缺失或无效时按0，不回退到添加/完成时间。平均上传速度沿用上传总量除以此累计时长。保留既有严格大于时间阈值的比较；“仅MoviePilot”仍按标签判断，不扩展历史归属。

平均上传速度缺少可信累计时间（含0）或上传量时返回未知，候选视图输出null；只在用户启用低速条件时阻止其命中。Transmission不再用分享率乘大小推算缺失上传量，真实上传量为0与未知分开。配置阈值（含换算后）必须有限、非负；下载器非有限/负数字段不进入比较，时长与分享率降为0，平均速度保留未知。

分类与状态沿用逗号多值配置，兼容中文逗号/换行，按完整值精确匹配；空或仅空白配置不限。条件非空且任务字段缺失时拒绝，不能通过空字符串的子串性质命中。

执行阶段将重读的全量任务重新构造快照，对原扫描主候选重新匹配全部AND条件；同数据辅种必须在当前标签池中仍与有效主候选名称及大小相同。失去条件的对象记跳过及原因，不执行动作，H&R检查仍保留。不会在执行阶段额外处理新的普通候选。

体积帮助与解析统一为最小值-最大值（GB，沿用原GiB换算），要求两个有限非负数且最小值小于最大值。保留开区间边界；逗号、多段、反向及无效输入报告配置错误，不静默忽略条件。

## Alternatives considered

保留墙钟计时能沿用既有候选数量，但不能代表实际做种，且存在提前删除风险，因此不采用。只复查hash不足以守住用户条件；本次复用真实快照与匹配器，而非另写一套执行过滤。支持逗号输入虽可兼容旧提示，但会形成双语法并掩盖错误提示，选择明确现有连字符契约。

## Consequences

累计时间缺失、暂停或历史计数较低的任务可能比旧版本更晚成为候选，属于预期安全收紧。重读与删除仍不是跨系统原子操作，无法消除回读之后外部改动的竞态；本次不承诺事务隔离。同数据辅种仍可按既有配置追加，但失去有效主候选时整组跳过。

离线测试通过真实scanner/criteria/run_cycle覆盖累计时间、缺失回退禁止、条件变化零动作、同数据主候选失效、体积错误与边界。旧展示历史测试使用完整CompiledConditions与快照替身，独立验证动作/历史契约，不作为筛选正确性的证据。不修改生产配置，不真实删种或部署。

新增边界测试通过真实cycle证明子串、空状态、负阈值和NaN/Inf不会触发下载器动作；证明合法零上传可匹配低速、未知平均速度不会匹配低速但也不阻碍未配置此条件的任务。
