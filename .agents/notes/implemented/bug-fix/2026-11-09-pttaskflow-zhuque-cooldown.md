# Agent Note: 朱雀技能的冷却周期与每日去重

Status: implemented

## Problem

朱雀技能复用每日任务引擎后，成功记录成为当天终态，独立 DateTrigger 后续触发仍被跳过。角色技能按冷却周期恢复，并非每天只能执行一次。

## Decision

Task 的 daily_dedup 默认开启，ActionTask 允许通过关键字参数关闭，仅朱雀 skill_release 声明为 False。引擎读取任务策略，不按站点域名或中文结果分支；执行结果仍写入历史并保留 terminal 语义，已有成功历史无须清除。升级、喊话等其他任务维持每日去重，引擎互斥不变。

朱雀保持原 ZhuqueHelper 的未来 next_time 最小值算法，没有未来值时返回当前时间；调度层统一增加 60 秒偏移，配置保存的仍是原始 next_time，重复注册不会累加偏移。保留独立技能 DateTrigger，主 Cron 不加入技能。

## Alternatives considered

- 让技能成功返回非终态：改动少，但把单次执行结果与重复执行策略混合，且不能兼容已经落库的终态成功记录。
- 引擎按朱雀域名豁免：容易局部修复，但违反引擎只消费任务契约的边界。
- 优先调度已经可释放的角色：可能减少等待，但改变原插件算法，本轮仅修复迁移差异。

## Consequences

技能可以在同一天多次调用 all 接口，是否可释放仍由站点判断；其他任务不扩大执行次数。未增加写请求失败后的即时重放。

离线回归使用真实 TaskEngine、朱雀任务声明与 Action，替换全部站点 IO，覆盖已有成功历史下连续两轮技能执行、升级去重、引擎互斥、部分角色冷却不拦截请求、未来时间算法及固定偏移。真实站点释放和 QNAP 部署不属于本轮离线验收。
