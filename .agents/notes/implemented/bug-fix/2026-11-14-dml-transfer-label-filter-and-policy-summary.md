# Agent Note: DML 转移标签硬筛选与独立于运行记录的配置摘要

Status: implemented

## Problem

转移规则配置包含标签时，旧 `empty_label_ok` 会让空标签种子绕过包含条件。任务列表的删除策略摘要依赖运行状态投影，禁用或尚未执行的任务显示未知，造成需要先执行可能带删除副作用的任务才能看清配置的误导。

## Decision

包含标签是硬条件，逗号分隔的非空标签去除首尾空白后须全部满足；未填写则不限制标签。排除条件仍独立生效。面板移除无标签开关和放行摘要，明确填写与留空的含义。旧字段的最终移除边界见[无标签兼容裁剪](../../implemented/simplification/2026-11-14-dml-obsolete-empty-label-option.md)。

任务配置列表直接依据当前表单解析继承或显式覆盖，不依赖任务是否启用、是否运行及状态请求结果。面板明确这是“按当前表单计算，保存后生效；规则关闭时不执行删除”，不宣称未保存草稿已成为后台运行策略。后端删源权限、H&R 闸门、全局默认值及真实执行逻辑不变。

这部分替代[共存现场协调](2026-11-02-dml-transfer-reconciliation.md)中配置列表只使用运行投影的决定，其余协调和删源约束不变。历史检索中[空标签定义清理](2026-11-02-dml-empty-tags-and-execution-feedback.md)处理的是零关联全局标签定义，不是转移候选筛选，互不替代。

## Alternatives considered

- 仅关闭当前规则的无标签开关：能止住这一条规则，但不能保证其他规则或新增规则遵守包含标签硬条件，也不满足未填写标签即不限标签的要求。
- 继续以运行投影作为配置摘要的唯一来源：可准确表示已保存的后台策略，却使关闭或未执行规则依赖运行数据；配置列表改为明确标识的表单预览，运行记录仍由后端提供。
- 在缺失运行投影时才回退表单：改动较小，但会让运行前后显示口径不同，旧响应还可能遮蔽最新编辑，故不采用。

## Consequences

旧配置中依赖 `empty_label_ok=false` 排除无标签种子、同时未填写包含标签的规则，现在不再排除无标签种子；这是用户确认的语义变化，部署前应复核相关规则。填写包含标签的规则不会再由该旧字段放行无标签任务。

配置摘要可即时反映编辑，不触发下载器调用，不操作真实任务。为避免误解运行状态，界面保留保存后生效和停用不执行的说明。

校验队列调查确认 `transfer()` 整轮持有 `_queue_lock`，worker 使用相同锁，批量添加时会延后校验。这里只记录已确认的限制，本轮不修改并发或扩大删源许可；分批添加与持续校验需单独设计和验证。

## Testing

标签筛选回归通过真实 `_run_task` 消费路径覆盖 qB/TR、包含标签硬匹配、未填写标签不限、排除优先及旧字段不同值；删除策略通过 Vue setup 与实际 SFC 渲染覆盖停用、未运行、缺失或旧状态、继承、显式覆盖及全局编辑。测试使用替身下载器/API，不代表 QNAP 真实下载器验收。
