# Agent Note: 标签补全执行历史排除未执行项

Status: implemented

## Problem

`_record_tag_outcome` 把正常的无变更结果写成 `observed`，页面将其翻译为“观察（未执行）”，即使用户没有开启观察模式。重复无变更项还占用了有限的历史容量。

## Decision

补全执行历史只写入已变更的成功结果与失败结果；无变更和仅观察预览不写入该流。失败仍保留，避免把识别、读取和写入故障隐藏成空白。补全统计与观察模式配置不改变。

`model/execution_history.py::query` 对 `tag` 流先过滤已有 `observed` / `skipped`，再执行筛选、排序和 API 分页，因而总数与页面一致。此读取不删除或保存旧数据，不改变 `tag_cleanup` 或其他流的观察记录。

## Alternatives considered

只将旧记录改名为“无变更”能消除观察模式误解，但仍让未执行项占据执行记录，不满足用户要求。仅在前端过滤无需改公共查询层，但会产生空页和错误总数，因此过滤放在后端查询分页之前。

## Consequences

补全记录只反映成功与失败；观察预览仍通过模块运行统计呈现，不再产生逐种执行历史。已有未执行数据保留，仍占存储容量直到历史自然裁剪或用户主动清理。回归覆盖写入四种结果、旧记录只读隐藏、其他流不受影响以及过滤后的分页总数。
