# Agent Note: DML 移除无标签放行兼容字段

Status: implemented

## Problem

[标签硬筛选](../bug-fix/2026-11-14-dml-transfer-label-filter-and-policy-summary.md)使无标签放行字段不再影响行为，继续把它暴露给 API、表单和迁移任务会让后续实现误以为它仍然有效。用户明确要求本轮只清理这一兼容链路。

## Decision

任务模型、API 摘要及表单模板不再定义或迁移 `empty_label_ok`，插件默认配置及运行时不再读取 `transferemptylabel`。Vue 任务解析丢弃废弃的无标签字段，保留其他未知属性的透传契约，不扩展清理范围。其他模块的迁移逻辑和删除策略三态兼容不变。

不执行配置清库或远端数据迁移。已保存配置中的旧键可以原样留在宿主存储里，通用表单透传的顶层未知键也不强制删除，但没有专用读写逻辑，不参与任何筛选。只有用户正常保存任务时，任务 JSON 才按当前模型序列化。

## Alternatives considered

- 保留无效字段来回写旧值：可以减少配置差异，但会保留误导性的公开契约，用户已明确选择清理。
- 同时清除远端历史配置：能使存储更整洁，却引入真实配置写入，超出代码清理边界，不采用。

## Consequences

兼容旧任务输入但不保留废弃的无标签放行属性。填写包含标签始终严格匹配；未填写始终不限制标签，旧键真假不能覆盖该语义。测试保留旧字段输入作为反例，而不是兼容实现。

只裁剪字段，不改变转移校验队列、H&R 闸门、删源许可或共享磁盘路径。
