# Agent Note: DML退出整理相关文件清理

Status: implemented

## Problem

复制、硬链接和保种场景中，成功整理后源路径仍存在是预期行为，不能据此认定为残留。TransferFailed 也不证明源文件可以删除，且事件可能来自手工整理。用户选择完全取消失败清理，而不是继续为两条文件级删除路径增加推断条件。

## Decision

DML不再注册失败清理事件、巡检调度、手动接口或配置与数据页入口。不再因整理成功、整理失败或重复源文件删除文件及下载历史。自动删种保留自己的条件与动作，不接管这些事件，也不以是否MP任务作为强制分流依据。

旧 failcleanup_* 键和持久化历史保留，不做数据清除；旧开关即使为true也不能激活模块。modules/failclean 中的服务和事件入口仅保留无IO兼容stub，旧代码调用不能恢复删除行为。其他有效模块的观察开关不得因表单裁剪丢失。

历史通知统一约定仍适用于有效模块，见[站点消息通知](../../implemented/architecture/2026-11-04-dml-site-message-notification.md)；该文讨论的失败清理调用方现已退役，其消息分类约定不因此翻转。本次检索未发现其他独立失败清理决策笔记。

## Alternatives considered

只删除成功整理残留巡检、保留TransferFailed即时删除，可以保留失败下载清扫能力，但失败事件仍不足以授权删除源文件，用户明确选择两者都取消。按MP归属分流到自动删种看似统一出口，但把当前用户配置误当成永久归属规则，并扩大自动删种候选范围，因此不采用。

## Consequences

整理问题交由宿主或用户处理，DML不再提供对应自动文件回收能力。旧历史仍留在存储中但不再新增或由退役页面清除。需要回退时必须明确恢复旧行为，不能仅打开遗留开关。

离线验证覆盖旧true配置门控、无事件/调度注册、兼容入口零IO，以及前端入口移除；全量后端与前端回归、联邦构建验证其他模块未因裁剪丢失必要字段。此次不部署、不连接真实下载器，不将离线验证冒充QNAP运行验收。
