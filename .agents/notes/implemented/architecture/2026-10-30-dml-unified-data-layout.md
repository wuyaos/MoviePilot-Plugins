# Agent Note: DML 数据页统一展示契约

Status: implemented

## Problem

逐模块布局确认后，桌面表格与移动卡片双模板仍会使表头、操作和空态分叉。不同模块又把当前候选、最近运行汇总和逐条历史混在相似的记录区里；统一外观不能顺便改变数据含义。

## Decision

七个业务模块共享标题统计、单行配置摘要、纵向业务表；总览与诊断保留各自的信息结构。`ModuleTable` 只负责展示、展开、分页事件和清记录事件，筛选、切片、API与确认仍归 `Page.vue`。`ConfigSummary` 复用该表而关闭分页；`RecordDetails` 使用已声明字段白名单，避免通用对象展开意外展示无关配置。

桌面与窄屏共用一套表格，通过容器横向滚动容纳列。做种校验归入转移，总览仅七卡。公共组件不推断业务保护、执行结果或下载器关联。

## Alternatives considered

- 保留移动卡片：窄屏更紧凑，但重复模板已经导致列、操作及状态表现不一致，因此改为单表。
- 用现有候选和最近快照填满历史表：可以立即展示内容，但候选不等于真实执行、快照不等于持久化历史，因此不采用。
- 在本轮新增五类后端历史存储：能填齐目标表，但涉及记录生命周期与写入契约，超出本轮纯前端布局范围；当前明确显示接口缺失，不虚构已完成的功能。

## Consequences

布局骨架与展示组件已经落地；部分配置摘要、今日指标和执行历史仍受现有只读接口约束，显示未提供或未知，而非假0。跨下载器站点合计单列汇总组，不复制到每个下载器下。后端、配置存储、调度、下载器操作与删除保护均不改变。

前端组件及Page回归、生产联邦构建提供源码证据，但不能代替MoviePilot宿主的九页点击、深浅主题和窄屏视觉验收。布局依据见 `docs/downloadmanagerlocal-page-layouts.md`；该工作文档被仓库忽略，不能把其存在当成已提交交付。布局已用于本地MP预览；QNAP未部署、未推送。

## 表格密度与控件一致性

失败归档的行操作收进 `RowActionMenu`，保留原有动作映射，并在单条删除前明确确认仅删除记录。名称和原因采用可选的列展示属性 `lines` 做两行截断，原始字符串和展开详情不截断，避免用删减数据来缩短行高。

筛选与分页统一复用 `CompactSelect`，而非仅给原生 select 套相似边框：两者现在使用相同 Vuetify 选择、键盘和禁用行为。`ModuleTable` 增加纯展示 `filters` 插槽，将筛选和已有操作分组；计数移至标题旁，footer只保留页码和分页控件。新增纯消费端真实 Vuetify/Chrome 测试覆盖两行行高、窄屏内部滚动、菜单禁用项、选择页大小事件顺序和完整详情；不接触下载器或真实记录。

## 外观基准回归宿主

用户选择已推送源码/QNAP现有外观为基准，而不是新增一套控件皮肤。共享表改用宿主 `VTable`，清理、分页和空态动作使用 `VBtn`；业务按钮采用既有 tonal，导航和更多操作使用 text，最终危险确认仍为 error/flat。标题图标恢复 tonal `VAvatar` 与 `VIcon` 组合，状态使用 `VChip`，不再用边框和圆角把徽标画成按钮。保留统一布局与单一横向滚动容器。选择值和 Teleport 菜单文字在真实 Chrome 消费端按 computed style 对比，避免只验组件标签而漏掉下拉字体。

## 转移配置分组与默认值呈现

转移基础页按用户确认收拢为“基础设置／转移策略／转移后操作”，任务列表仍是独立页签。做种校验与重命名共用转移后操作区，三个开关同组同排，窄屏自然换行；不按每个开关继续拆标题。

不展示“新任务默认值”独立设置区，但不删除或重置已存的 `transfer_delete_source_default`、`transfer_delete_duplicate_default`。新建任务选择器将 `inherit` 显示为“默认（开启／关闭）”，依旧保存 `inherit` 而不固化为布尔值；显式开启、关闭和旧任务缺字段的兼容行为不变。这比在隐藏默认区时顺手回写 false 更能保留已有任务的生效语义。测试同时覆盖保存时保留两项配置、三态往返与后操作三开关在宽屏同排。

H&R 站点规则摘要改用共用数据表的表头字重、正文密度、轻分隔与低对比边框，继承值采用无底框的次要色文本并带“继承”字样，显式值与继承值可辨；来源仍是状态徽标、不能冒充按钮。固定密度只用于此 H&R 配置页，同一张表在窄容器内滚动。Chrome 实测 light/dark、宽/窄容器均保留 13px 正文与表头、继承样式透明无边框且非斜体，继承/显式颜色不同。

H&R 基础页与站点规则编辑使用同一组表单宽度：桌面内容最大 52rem，成组字段等宽且单个输入控件最大 220px；站点规则行内编辑器最多两列，短数值与开关保持原顺序，窄容器切单列并以容器宽度扣除边距限制编辑器。测试覆盖宽桌面每行字段 ≤832px、同轨等宽，360px容器字段可读且无页面溢出；站点编辑器窄屏约257px，内部控件不随表格最小宽度伸到728px。


H&R基础设置将通知模式、汇总计划、检查间隔合并进同一字段行；跟踪策略首行按下载器、站点白名单、刷流插件排列，第二行仅排除标签和排除分类。宽屏每输入控件≤220px，窄屏按既定网格折行；字段模型和事件不变。
H&R基础页和站点规则字段在等宽列内控件最大220px。站点规则徽标不再铺满网格，按内容收缩；八个规则字段采用稳定且随宿主主题适配的独立配色，表格和“更多”弹层共用映射。颜色表达规则类型，而不再只表达显式/继承；显式值用 tonal、继承值用 outlined 并保留“继承”字样，避免纯色觉区分。来源和启用状态保持独立语义。通知开关映射已有 hr_notify 三态，不新增持久化字段；关闭设为 none，本次表单内重开恢复上次 always/on_error，计划字段保留不清空。浏览器组件回归覆盖深浅主题、窄屏、八色、徽标按文字收缩与通知开关保存映射；宿主最终视觉仍需人工确认。

## 全配置输入类型与剩余模块布局

多值输入按内容类型分工，而不是把所有数组都转为标签。普通短值用 `MultiValueInput` 回车确认标签；路径、Tracker及逐行编辑内容保留文本域，数组路径通过 `MultiLineInput` 展示成行并在用户编辑后还原数组。拒绝把已有字符串自动改成数组，也不在挂载时修剪、去重或回写历史值。自由输入使用同一组件，受下载器/站点候选约束的多选继续使用原选择器，避免允许无效候选。中文输入法组合期间的回车只确认候选，不提交标签。

剩余五模块沿用已批准的分组与紧凑表单网格，不为每个开关再新增标题；分类/站点映射行编辑、上传限速规则仍保留各自结构。底部恢复默认和保存配置放到同侧，恢复仍需确认、取消与切换数据页仍是独立动作。真实消费端浏览器覆盖五模块八页签在1100/360px及深浅主题下的36px单行字段和无外溢；仅组件消费端测试，不能代替宿主人工预览。

分类映射的来源已按用户纠正改为读取 MP 的 media/category 配置投影，不再手工输入，也不将插件固定默认清单冒充当前分类。只读载入和刷新不回写映射；未编辑的新分类按原名写入，只有目标发生编辑才创建映射。MP 删除或改名后，旧映射仍独立保留并标注，可由用户移除；请求失败保留已有列表并明确报错。此方案替代上一版“来源点击编辑”。上传站点规则仍保留手填自定义名称，不依赖站点库候选，匹配沿用后端原有站点识别语义。

上传限速基础设置使用同一紧凑网格，不额外拆小标题；观察提醒与下载器字段分层，移除重复的 KiB/s 换算段落但保留宽限行为说明。紧凑开关尺寸覆盖整配置页和编辑弹窗，底部查看数据/取消统一为小号文字按钮，恢复/保存继续保持原动作层级。自动删种真实模式提示增加底部间距；字段错误消息保持可见，不能为了紧凑用 hide-details 隐藏下载器必选错误。
